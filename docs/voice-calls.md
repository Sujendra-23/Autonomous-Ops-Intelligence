# Voice calls: Twilio phone agent that books appointments

Inbound phone calls are answered by a small Claude agent that collects the caller's
name, what they need, and a preferred time, then books it into Google Calendar.

```
caller ──PSTN──▶ Twilio ──POST /voice/twilio/incoming──▶ backend (verifies X-Twilio-Signature)
                    ▲                                        │ TwiML: <Say> greeting + <Connect><Stream wss://…?token=…>
                    │                                        ▼
                    └──── 8 kHz mu-law frames ───▶ /voice/twilio/stream (WebSocket, HMAC stream token)
                                                      │ mu-law → PCM16 → resample to the STT rate
                                                      ▼
                                           StreamingTranscriber (live_stt.py: Deepgram / OpenAI)
                                                      │ final transcript segments
                                                      ▼
                                   VoiceAgent (Claude, forced `record_turn` tool call)
                                     │ reply text                      │ name + need + time confirmed
                                     ▼                                 ▼
                         Twilio REST: update the call's TwiML     GoogleCalendar.create_event
                         (<Say> reply, re-open <Stream>)          (idempotent id, conflict check)
```

## What is and is not verified

| Piece | Status |
|---|---|
| mu-law decode, resampling, signature check, stream tokens, TwiML, agent logic, calendar insert/409 handling, webhook and WebSocket routes | Unit tested with fakes (`tests/test_voice_*.py`), no network |
| Real Twilio call, real Media Streams audio, real STT provider, real Claude call, real Google Calendar write | **Not run.** Everything provider-facing is mocked in tests. Treat first contact with each provider as untested. |
| Latency | Unmeasured. Each spoken reply is a Twilio REST call update plus a new media stream, so expect a noticeable pause per turn. |

## Setup

1. **STT.** Set `STT_PROVIDER=deepgram` (or `openai`) and its key, as for the live note-taker.
   The default stays `STT_PROVIDER=none`; with `none` the webhook answers with an apology and hangs up.
2. **Claude.** `ANTHROPIC_API_KEY` is required. `VOICE_AGENT_MODEL` overrides `ANTHROPIC_MODEL`.
3. **Twilio.** Set `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, and `TWILIO_PUBLIC_BASE_URL`
   (the public `https://` origin Twilio reaches, e.g. an ngrok URL; no trailing path). In the Twilio
   console set the phone number's *A call comes in* webhook to
   `POST {TWILIO_PUBLIC_BASE_URL}/voice/twilio/incoming`.
4. **Calendar writes.** The existing connector was read-only. Booking needs a refresh token granted
   `https://www.googleapis.com/auth/calendar.events` (the read-only scope will fail with a 502 on
   insert) **and** `GOOGLE_CALENDAR_WRITE_ENABLED=true`. Without the flag, the agent tells the caller
   someone will call back instead of claiming a booking.
5. Optional: `VOICE_BUSINESS_NAME`, `VOICE_TIMEZONE` (default `America/Chicago`),
   `VOICE_APPOINTMENT_MINUTES` (default 60), `VOICE_MAX_TURNS` (default 8).

## Security model

* The routes live at `/voice/twilio/*`, **outside `/api`**, because Twilio cannot send our bearer or
  OIDC credentials and `SecurityMiddleware` only gates `/api/*`. They authenticate themselves:
  * `POST /incoming` requires a valid `X-Twilio-Signature` (HMAC-SHA1 of the configured public URL
    plus sorted form fields, constant-time compare). The URL is rebuilt from `TWILIO_PUBLIC_BASE_URL`,
    not from request headers. Missing or invalid signature gives 403; unconfigured gives 503.
  * `/stream` requires a short-lived (1 h) HMAC-SHA256 token, minted by the verified webhook and bound
    to one `CallSid`; the `start` frame's `callSid` must match it. The token is used instead of
    relying on how Twilio signs the WebSocket handshake. STT, Claude and Twilio clients are only
    constructed after the token check passes.
* All credentials are `SecretStr` and unwrapped at the point of use; Twilio response bodies are never
  logged or returned.
* In OIDC multi-tenant mode voice uses deployment-level settings, not per-workspace connectors.

## Behaviour and limits

* Claude is forced to call a `record_turn` tool (name, need, `requested_start`, `ready_to_book`, `reply`).
  The agent only books when `ready_to_book` is a real boolean `true` **and** all three slots are
  present and the time is in the future; the confirmation read to the caller is generated by code, not
  by the model.
* Before inserting, the agent lists calendar events in the slot and asks for another time if one exists.
* The Google event id is a SHA-1 hex of the `CallSid`, so retries are idempotent (HTTP 409 is treated as
  "already booked").
* Turns are capped (`VOICE_MAX_TURNS`); on cap, LLM failure, or calendar failure the caller is told
  someone will call back.
* Call state is held in process memory (a media stream is re-opened after each spoken reply, so state
  outlives one WebSocket). Run one backend replica for voice or add sticky routing; moving it to Redis
  is a natural follow-up.
* Not implemented: persisting call transcripts as `Transcript` rows, business-hours rules, SMS
  confirmation, barge-in (caller speech during a `<Say>` reply is not interrupted), call recording.
